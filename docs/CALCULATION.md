# 计算口径：v13 开局简化模型

本文描述当前程序实际采用的计算过程。「本模型」「当前实现」不表示游戏规则已获验证；请结合 [来源](SOURCES.md) 与 [已知问题](KNOWN-ISSUES.md) 阅读。

## 输入与坐标

- 地图为 4 行 × 9 列。界面位置为从 1 起算的「行-列」，行从上到下，列从左到右；API 的 `r`、`c` 从 0 起算。
- 方向为 `R` 右、`D` 下、`L` 左、`U` 上。部署按列从左到右、同列从上到下排序，与鼠标放置先后无关。
- 页面休整期层数范围为 0–999，自动加层后可能超过 999。
- 页面限制场上 8 名、整备区 6 名；直接调用引擎不会完整执行页面容量限制，调用方须自行校验。
- 地面允许当前库内所有干员；高台允许远程干员和歌蕾蒂娅；其余格不可部署。
- 地图装置与特殊地形的伤害和属性效果不自动应用。

## 激活人数

```text
激活人数 = 初始场上不同名字的阿戈尔人数 +（有调和 ? 1 : 0）
```

达到 3 启用阿戈尔生命加成、开局自动加层与吞噬；达到 6 启用前 3 名阿戈尔倒地处理。调和可以发起与参与吞噬，倒地不占阿戈尔名额。同名阿戈尔不重复增加激活人数，多名调和合计只加 1。判断基于初始场上，不在吞噬、倒地或替补后动态重算。

## 基准面板、潜能与持有练度

普通/精锐分别读取一个快照状态，不表示局外精英化档位。按 `panelOf`，当前生命、攻击、防御采用：

```text
面板属性 = round_to_0.1((快照状态值 + 潜能平加 + 选中模组平加) × (1 + 对应持有练度系数))
```

模组仅在状态 `moduleLevel > 0` 且有模组数据时叠加；等级取该状态的记录。Ⅰ/Ⅱ选择模组类型，不能任意选择模组等级。潜能仅提取 ATK、MAX_HP、DEF 的平加项，不模拟其他潜能效果。

| 局外档位 | 攻击 | 防御 | 生命 |
| --- | --- | --- | --- |
| 精0 | 0% | 0% | 0% |
| 精1 | +5% | +5% | 0% |
| 精2 Lv1–59 | +10% | +5% | +5% |
| 精2 Lv60 及以上 | +10% | +10% | +10% |

页面全局默认精2 Lv60 档；个体未覆盖时跟随全局。API 省略 `own` 时默认无持有加成，与页面默认不同。

这里仅描述运算顺序。快照状态值的加工过程、模组是否可能重复计入、持有档位与游戏的对应关系尚未逐项复核。资料弹窗显示的是基准值，不随个体设置更新，不能直接当作最终战斗面板。

## 吞噬前开局层数

盟约激活后，以输入的休整期层数为起点：

| 来源 | 普通 | 精锐 | 当前实现 |
| --- | --- | --- | --- |
| 魔王 | +10 | +20 | 每个初始场上实例计1次 |
| 幽灵鲨 | +1 | +2 | 每个初始场上实例计1次 |
| 斯卡蒂 | +4 | +8 | 每个初始场上实例计1次 |
| 浊心斯卡蒂 | 每次+2，上限20 | 每次+4，上限40 | 仅计部署顺序在其之后、且在其朝向攻击范围内的其他初始场上实例 |

同名实例在当前程序中分别加层。程序没有跨回合历史、已用次数或既往部署记录，不能证明同名共享上限、每回合/每场上限符合游戏。

盟约未激活时保留输入层数，不额外加层。安哲拉击倒叠层、替补部署和傀儡切换等产生的其他触发未完整补算。

## 初始生命与攻击

令 `L` 为吞噬前开局层数：

```text
阿戈尔生命比例 = 已激活 ? (35 + L) / 100 : 0
生命上限 = round(面板生命 × (1 + 阿戈尔生命比例 + 额外生命% / 100) × Pith倍率)
初始攻击 = 面板攻击 × Pith倍率 × (1 + 额外攻击% / 100)
```

盟约·辅助干员的 Pith 倍率为普通1.2、精锐1.4，其余为1。当前库只有阿戈尔和调和，场上实例按上式处理。

页面固定 `applyTalents: false`，不自动计算原天赋；内部 API 的该选项也只处理有限生命项，并非完整天赋开关。额外防御输入未参与数值或伤害减免。

生命上限在生成标记前一次算定，不随吞噬参考叠层回算。

## 吞噬标记与继承

按部署顺序为每个阿戈尔或调和实例生成链：取链节点朝向前一格目标，生成「发起者→目标」标记；目标若为阿戈尔或调和，再沿目标朝向继续。遇到空格、已访问实例或本模型禁止的反向吞噬关系时停止。

全部标记生成后，先按每名发起者的全部标记累计目标的 `panel.atk` 和 `panel.block`，然后处理伤害。继承基准不含目标额外攻击百分比、Pith百分比或已继承数值。

伤害阶段取消标记时，当前程序不回滚此前继承。因此标记关系不等于实际扣血关系，是否符合游戏仍需验证。

## 伤害、傀儡与复起

有效标记按生成顺序直接扣目标5000生命，不模拟防御、护盾、减伤、属性互动或真实时间轴。这是模型假设，不能写成已核实的游戏伤害类型。

- 已倒地或已进入本模型傀儡状态的目标，其后续标记取消。
- 归溟幽灵鲨首次致命后，按满血、阻挡0的傀儡处理，不记入倒地列表；本次开局剩余标记不再伤害傀儡，不模拟持续时间与本体回归。
- 精锐斯卡蒂选择「潮湿的剑袋」且未用过复起时，生命上限乘0.6并四舍五入，回复至该上限，不记入这次倒地；之后再次致命可以倒地。倍率与触发时机仍需核对。
- 其余致命扣血按顺序记入倒地列表，从场上移除。

原包中傀儡「同次开局第二次吞死」的表述不符合当前实现。无敌时长与模组占位参数尚未完整验证。

## 6人档倒地处理

伤害全部结束后，若初始激活人数达到6，处理倒地列表中的前3名阿戈尔实例：

| 策略 | 当前处理 |
| --- | --- |
| 猎人战法 | 整备区从右向左找未使用、属于阿戈尔且能部署到倒地格的实例；读取普通/精锐、练度、潜能和模组，沿用倒地实例朝向；没有则留空 |
| Pith | 原地回满生命，重置继承攻击和阻挡，不取整备区替补 |
| 其他 | 仅按通用阿戈尔原地复活处理，不模拟其他具体策略效果 |

调和倒地不占名额；傀儡切换或斯卡蒂复起未记入倒地列表时也不占名额。

当前为先结完初始伤害、再批量处理复活/替补，不模拟即时插入时序。替补不带入整备区额外百分比，不重跑完整部署、吞噬和叠层。替补仅在结果视图展示，不实际消耗编辑阵容中的整备区槽位。

## 参考叠层与显示边界

`layersFromDevour` 将全部标记的唯一目标按等阶汇总，包括后来取消的标记。它不回算本次生命，不自动叠加到输入框，也不是已验证的下一回合增量。

细则表主要列初始场上实例，替补无完整独立数值行。攻击列在没有继承时可能只显示基准值，未完整展示手动百分比。盟约未激活时，摘要的 `35 + L` 仅为参数，并非实际生命加成。

改变算法前应提供实战依据与可复现用例，独立提交修改；不要仅通过修改说明宣称问题已解决。
